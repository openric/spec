Records in Contexts, served over HTTP - implementation-neutral, IIIF-inspired.

OpenRiC is an open specification for how archival descriptions map to RiC-CM / RiC-O, how that data is served over HTTP for both reading and writing, and how graph-based interfaces can render it consistently across any conformant server. Not a product. A contract anyone can implement.

Get started in 15 min → Read the spec ↗ Try the API ↗ Conformance probe ↗ GitHub ↗

In plain language: OpenRiC lets different archival systems publish, exchange, validate, and explore RiC-based archival data in a consistent way. It's a shared contract - like IIIF for images, but for archival description. Any system that implements it can be read, written to, and graph-walked the same way. Not a developer? Try the archivist view instead.

ric.theahg.co.za
Clients
Viewer, Capture, Explorer

Three pure-browser apps that talk to any conformant server - not just the reference. 2D + 3D graph rendering, data capture, Swagger UI. No privileged access; they use the same HTTP contract adopters see.

viewer · capture · api-explorer
Related platform
Heratio

An existing GLAM platform from the same maintainers, with RiC built in. It can read graph data from the Reference API over HTTP, but it still writes through its own copy of the RiC routes on a database it shares with the reference service. So it is not independent evidence that the contract alone is enough for a production archive. AGPL.

heratio.theahg.co.za

If you only remember one thing: OpenRiC is the contract; Heratio is one consumer of that contract. The contract is deliberately designed so that any archival system - not just Heratio - can speak it.

Where things stand

April 2026

v0.1.0 to v0.37.0 done

The base documents, then one release per profile from v0.30.0 (Core Discovery) to v0.36.0 (Export-Only), then the RiC-O 1.1 namespace remediation in v0.37.0. The changelog has every release.

Now

Part I - the Standard current

A release that can be verified, implemented and reviewed without relying on our own systems: change control, the API contract, release bundles with checksums, the known-issues log, and an external technical review. It ends at the Standard Acceptance Gate. See current status.

Next

Part II - OpenRiC Workspace planned

The archival application, built on the accepted Standard. Work on it starts only after the Standard Acceptance Gate is signed.

v1.0

v1.0 freeze planned

Bound to the governance criteria: a second independent implementation passing conformance on any profile, an external institution committing to deploy, and active contributors from outside the maintainers.
