# OpenRiC API Vocabulary v1

**Namespace IRI:** `https://openric.org/ns/v1#`
**Preferred prefix:** `openric`
**Issued:** 2026-10-15 · **Licence:** [CC-BY 4.0](https://creativecommons.org/licenses/by/4.0/)
**Machine-readable vocabulary:** [v1.ttl](v1.ttl) (Turtle)

## Purpose

OpenRiC uses two namespaces of its own, and neither is part of Records in Contexts:

- **`openric:`** (this page) is for the API itself: how lists are paged, how a server describes itself, how errors are reported, how a viewer is given a subgraph, plus three annotations the profiles put on entities.
- **`openricx:`**, the [extension ontology](/ns/ext/v1.html), is for archival meaning that RiC-O 1.1 does not yet model.

Every term below was already used by the profiles, schemas, fixtures and the reference service before this page was published on 2026-10-15; the namespace had been bound in responses without a vocabulary behind it ([mapping O-6](/spec/mapping.html#11-open-issues)). Publishing it changed no response. CI now fails if a schema or fixture uses an `openric:` or `openricx:` term that neither vocabulary defines.

## Entity annotations

| Term | Used on | Meaning |
|---|---|---|
| `openric:localType` | Places, rules, activities, functions, things | The implementation's own subtype (`country`, `law`, `production`, `box`), next to the canonical `rico:` type. It never replaces a `rico:` type. |
| `openric:jurisdiction` | Rules | Free-text jurisdiction (`Egypt`). Where the jurisdiction is a known place, `rico:hasOrHadJurisdiction` to a `rico:Place` is preferred. |
| `openric:role` | Corporate bodies | Viewer convenience, e.g. `repository` for an ISDIAH institution. |

## Versioning

The `/v1#` path is stable. Terms are added within `v1` and never removed from it; a term that is replaced is marked `owl:deprecated` with `dcterms:isReplacedBy`, as [change control](/spec/change-control.html) requires.
